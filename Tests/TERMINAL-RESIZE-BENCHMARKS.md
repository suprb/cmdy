## Endpoint and visible work

The proposed metric is the first complete **generated-cell viewport** on the
WindowServer display clock after one native public `AXSize` request. It does not
measure text-glyph correctness. Each row contains only colored space cells, and
all 120 or 132 target columns are observed, including the last column.

Version 2 preserves the original two grids, 120×36 and 132×40; the primary-screen
history; six counterbalanced process pairs; and 42 alternating transitions per
process, with exactly two explicit warmups and forty measured events. It preserves
the exact 1,000 logical history rows of 145 printable bytes plus CRLF, totaling
147,000 bytes, followed by 36 separator CRLFs. The nominal font remains Menlo
Regular 14. Actual rows and columns come from the owned worker's native PTY,
not a font-size estimate or requested window size.

Each colored row has a start sentinel, the 60 hexadecimal digits encoding the
128-bit nonce, resize sequence, columns, rows, row ordinal and CRC32, then one
deterministic color class per remaining interior column, and an end sentinel at
the actual right edge. Each extra class is the low four bits of CRC32 over
`<60-digit-word>/<four-digit-hex-absolute-column>`. Classes 0–15 use the fixed
16-color palette; classes 16 and 17 are the distinct sentinels. A row-major byte
array of these class indices gives the independently reproduced viewport hash.
The native decoder infers each cell's class from its actual pixels and requires
all nine samples to agree; expected words do not supply the observed class.
The first matching frame retains that row-major byte stream as bounded base64
(at most 7,040 characters), and derives its count, hash and row words from it.
Python decodes those observed bytes and checks every cell against its independent
generator. A producer-supplied success flag or hash cannot replace the stream.

The worker first paints neutral spaces over the entire viewport, then paints
every colored cell. Repaint sizes are **92,600 bytes at 120×36** and **112,968 bytes
at 132×40**. These sizes do not vary by nonce or sequence because escape fields
have fixed widths. Each offered/completed byte count and SHA-256 is retained and
recomputed by the independent validator. The fixture never uses an alternate
screen, erase-scrollback, synchronized output, DSR, or a direct PTY size setter.

The private v1 prototype remains unchanged at
`/private/tmp/cmdy-parity-20260909/resize/runtime-05`. It checked only 62 cells per
row and left the text tail unobserved. Its captures, calibration and timings are
not v2 evidence and must never be pooled with v2 or relabeled as qualified.

## Native request, observation and ownership

`resize_action.swift` makes exactly one `AXUIElementSetAttributeValue(...AXSize...)`
call. The start is `mach_absolute_time()` immediately before that call; its return
clock is retained separately. All AX lookup, control IPC, source checks and
process spawning occur outside the start. No measured action activates,
repositions, refits or retries the window. Only the app's normal handling of its
public window resize can change the worker's actual PTY dimensions.

`resize_worker.py` arms one new sequence through a capability-protected private
Unix socket. Arming does not paint. A new real SIGWINCH **and** matching
`TIOCGWINSZ` are required to consume that sequence. A nonblocking signal wakeup
pipe avoids adding a polling interval to the response. The worker retains exact
signal, ioctl-observation, write-start and write-return clocks; a socket ACK or
write return is never a visible endpoint. Unsolicited geometry changes fail.

`resize_observer.swift` uses one persistent, fixed-resolution full-display
ScreenCaptureKit stream at the pinned display's native pixel dimensions, BGRA
sRGB, requested 120 Hz, queue depth three, without cursor or audio. It retains
metadata, never a screenshot. Pixel discovery and matching access only the
verified owned window crop. A window-only rescaled stream cannot qualify. Both
process start identities, executable hash, foreground app, exact window ID,
unoccluded native bounds and display mode are checked. The shared repeated
kernel-parent-link proof binds the worker to the app. The actual final PTY grid
and a fresh ancestry proof accompany each event.
The display signature includes its mode ID and flags, logical and pixel
dimensions, refresh rate and rotation. It is frozen in calibration and the
observer announcement, then checked on every ownership proof; a refresh-rate or
rotation change cannot pass merely because pixel dimensions stayed the same.

Calibration discovers the full-width sentinels and every row from an untimed
generated frame; no manually chosen crop or timing-sample fitting is supported.
The learned palette must stay within the nominal discovery tolerance of 12 and
maximum channel deviation from its median of three; the actual frozen matching tolerance is exactly
three. Geometry must contain the entire target viewport. Matching checks nine
interior samples in **every one of 4,320 or 5,280 cells**, with exact row context
and alpha at least 250. Python and Swift independently reproduce all cell
classes, history bytes, visible spaces and hashes.

The endpoint is `SCStreamFrameInfo.displayTime` for the earliest post-request
complete frame whose entire generated viewport matches at the target native
bounds. Capture callbacks and frames may precede AX return. Display time may
also exceed its callback clock; signed offsets are retained without clamping or
substitution. The first match is never replaced by a later frame.

An event retains all complete-frame checks and all SCK statuses from arming
through validation. They must have an exact one-to-one ordered correspondence;
missing or duplicate complete records fail. A later incorrect complete frame,
blank/restarted capture after the first match, suspension, capture stop, timeout,
ownership change or clock inconsistency fails the event. Static `idle` statuses
are permitted during the original 50 ms stability check; they cannot establish
a new visible endpoint. Final validation encloses both display and callback
clocks, remains within the three-second event deadline, and never adds stability
time to the reported request-to-frame latency.

## Tools and present admission boundary

These commands perform only planning, validation, compilation or generated tests:

```sh
python3 -B Tests/resize_recorder.py --status
python3 -B Tests/resize_controller.py --prepare /private/tmp/cmdy-resize-v2-plan
python3 -B Tests/resize_build.py --output /private/tmp/cmdy-resize-v2-headless
python3 -B -m unittest discover -s Tests -p 'test_resize_*.py' -v
```

Output directories must be new. The build command compiles the observer and
runs only the two generated CPU test executables. It never launches the observer.
Set `RESIZE_PTY_TEST_OUTPUT` to a new evidence directory to preserve the generated
PTY test receipts. Those tests resize only PTYs created by their own subprocess
harness; they launch no terminal application.

`resize_recorder.py --record-diagnostic` is a separate native entry point for an
already owned, prepared app and worker. It requires a JSON request, a separately
built observer and its matching source/binary manifest, and a new output
directory. The request contains `schemaVersion:1`, `qualifying:false`, nonce,
native spec, worker ready receipt/capability, source and target calibrations,
source sequence and one planned event. The native spec binds PID, worker PID,
TTY path, executable SHA-256, window/display IDs, nonce, power/thermal state and
bounded lifetime. It neither launches nor cleans up the caller's app or worker.
The request also includes `sourceDiscovery` and `targetDiscovery`, each with the
exact native discovery preimage and its SHA-256. Their geometry and palette are
independently reconstructed before launching the observer and must equal the
source and target calibrations exactly.
Before either component is armed, both discoveries must also match the
observer's complete app start identity, window/display IDs, display signature,
capture resolution and display bounds. Source and target crops remain bound to
their respective event bounds. Discovery clocks must precede the native request.
The calibration nonce may differ from the event nonce; a calibration from a
different app lifetime or window cannot be reused through this diagnostic
entrypoint. Such reuse needs a separate explicit provenance contract. Earlier v2
metadata lacking the display-mode pin is not accepted by the strengthened
validator.
Its one child observer is stopped and reaped on success or failure, and partial
native records and cleanup receipts are retained. It is **not** a campaign or a
parity entry point.

`resize_evidence.py EVENT.json` independently recomputes a diagnostic event's
generated bytes, every-cell hash, row CRCs, raw first-frame selection, clock
math, request/signal/paint order, final native grid and repeated ancestry. Its
successful result is `diagnosticValid:true, qualifying:false`. The `--qualify`
option always exits with a blocked result; there is no override that admits an
old export receipt or a synthetic event. Complete campaign admission goes through
`resize_parity_evidence.py`, not this standalone-event entry point.

## Native prerequisite and complete batch integration

The standalone pilot above followed the preserved native export plan (`results/2026-09-10-scrollback-export/NATIVE-EXPORT-PLAN.md` in the private performance notes)
before any paired measurement. The documented public actions are only candidate
transports: their existence does not establish safe path delivery, isolation or
equal export contents. Every block still needs fresh disposable processes with private
TMPDIRs and the unchanged 147,000-byte history corpus. Accept only a bounded path
receipt from the owned raw PTY, confined to the exact private TMPDIR; read only a
new owned regular 0600 file with no symlink following, size bound and repeated
descriptor identity checks. Recognize only the exact generated history and
allowed generated blank viewport/separators. All 1,000 logical rows must appear
once in order; visible-only export, pruned prefixes, reordered/duplicated rows or
unrecognized content fail. Never use the system clipboard, inspect its metadata,
or invoke selection/copy as a fallback.

The complete campaign requires raw export receipts and
independent validation before and after each complete block, prove the native
viewport is unchanged after export, and take a fresh post-export frame. Freeze
new v2 per-app/per-profile calibration, source/binary/config/display/power pins,
then record all six complete pairs without retrying or discarding individual
events. Preserve all failures and cleanup, retain warmups explicitly, and feed
only validated v2 measured events into the unchanged public paired p50/p95 gate.
